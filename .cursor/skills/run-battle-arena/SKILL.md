# Run a driver versus a driver

TypeScript. Docker only ([ADR 0011](docs/decisions/0011-docker-only.md), [ADR 0019](docs/decisions/0019-battle-arena.md), [ADR 0023](docs/decisions/0023-arena-any-driver.md)). Simulation: [docs/domain/battle-arena.md](docs/domain/battle-arena.md). Match math: [docs/domain/match-play.md](docs/domain/match-play.md).

## Steps

1. Read those domain docs plus [docs/domain/game-engine.md](docs/domain/game-engine.md) and [docs/domain/gnubg.md](docs/domain/gnubg.md). Shared loop is `ts-core/sim`; drivers live in `battle-arena`. Each side (`--a`, `--b`) is `game-engine`, `game-engine-fast`, `teacher`, `hedgehog`, or `xg`, including the same driver twice. `game-engine-fast` is the GPU engine ([docs/domain/game-engine-fast.md](docs/domain/game-engine-fast.md), [ADR 0028](docs/decisions/0028-game-engine-fast.md)): same `/evaluate` as game-engine plus `?ply=N`; start it with `docker compose up -d game-engine-fast`. `xg` is eXtreme Gammon 2 through the host GUI sidecar in [docs/domain/xg.md](docs/domain/xg.md) ([ADR 0025](docs/decisions/0025-xg-gui-sidecar.md)): start XG and `docs/integrations/xg/xg-sidecar.ps1` first, pass `-e XG_BASE_URL=http://host.docker.internal:8091`, keep matches short. It plays XG's top move and XG's own double/take; never read or modify XG itself, and never dump from it. Hedgehog is the external sidecar in [docs/domain/hedgehog.md](docs/domain/hedgehog.md) ([ADR 0030](docs/decisions/0030-hedgehog-plays-itself.md)): build the image (`docker build -t hedgehog-getmoves docs/integrations/hedgehog`; rebuild when the sidecar changes, the client needs `/health` `api: 2`), pass `-e HEDGEHOG_BASE_URL=http://host.docker.internal:8090`. It plays Hedgehog's top move at the cube and score and Hedgehog's own double/take. Do not vendor or port that engine, its tables, or its `.ogxf` weights, never publish the image, and never use its output as training data. `ply` is GnuBG, per side: hedgehog 0–1 (default 1), `game-engine-fast` 0–4 (default 0); above the driver maximum is an error, other drivers drop it and warn. Hedgehog's sidecar uses those numbers.
2. From `battle-arena/`, use Compose — never run `battle:inner` / `test:inner` on the host. Commands: [README.md](README.md). `docker compose up -d` starts teacher + game-engine. Tests: `docker compose --profile test run --rm test`. Battle: `docker compose --profile arena run --rm arena npm run battle:inner -- --matches 1 --seed 1 --length 7` (`--no-cube` for checker-only). A `game-engine` side requires `training-ground/checkpoints/cubeless.onnx`.
3. Both sides play **max strength**. Checkers: argmax **mover MWC** (teacher also `teacherDiff` then `stepsKey`); `xg` and `hedgehog` play their engine's top move instead. Re-rank game-engine `/evaluate` results; do not use money cubeful order. Cube: infallible `evaluateCube` (the `xg` and `hedgehog` sides use their engine's own) unless `--no-cube` (checker-only; cube stays 1). Skip cube on the opening roll; skip at cube 64. Alternate seats each match.
4. Write `battle-arena/replays/<batch-id>/<matchId>.sgf` (`FF[4]` `GM[6]`, `AP[battle-arena:1]`). Print match-win summary. Do not write training JSONL. Never commit `replays/`. Open SGF in `gui` (`docker compose up --build` in `gui/`) or gnubg.
5. Have the `backgammon-rules` subagent check sample positions and chosen `steps` (Crawford `mayDouble`, gammon/BG).
